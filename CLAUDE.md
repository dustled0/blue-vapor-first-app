# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Single-page HTML inventory/POS system for a small grocery store ("Honesty Store"). No build tools, no backend, no framework. Uses xlsx-js-style (SheetJS fork with cell styling) via CDN for Excel export, Google Fonts (Geist + Geist Mono + Material Icons Round) for UI.

## File Structure

- `index.html` — All UI, styles (CSS variables + dark mode), and application logic
- `data.js` — Base product catalog, customer list, and constants (products can also be changed in the app, see Product catalog; edit this file to change customers or to bake in-app product changes in)
- `catalog.js` — Pure catalog logic (`window.Catalog`: build/sort/normalize, mutations, `parsePaste`, `toDataJs`), no DOM, unit-tested
- `tests/` — `catalog.test.js` (run `node --test tests/*.test.js`) and `tests/e2e/*.e2e.js` (run `bash tests/e2e/run.sh <file>`; Windows Node + Chrome over CDP, screenshots land in the gitignored `tests/e2e/out/`)
- `manifest.webmanifest`, `sw.js`, `icon.svg`, `icon-192.png`, `icon-512.png` — install-as-app + offline support. `sw.js` is network-first for the app's own files (so edits to `index.html` / `data.js` show up) and cache-first for CDN fonts / xlsx-js-style. It only registers over http(s); opening `index.html` as a file skips it. Bump `CACHE` in `sw.js` if cached files must be dropped.

## Architecture

- **Data layer (`data.js`)**: `PRODUCTS` (with `name`, `price`, `category`), `CUSTOMERS`, `HOT_WATER_PRODUCTS`, `HOT_WATER_FEE`, `HOT_WATER_FEE_OVERRIDES`. Products are displayed in array order (changeable in-app, see Product catalog; `PRODUCTS` is refilled in place). Each product has a `category` field used for section headers in the UI.
- **Categories**: Cigarettes, Detergents, Drinks, Flakes, Hot Water, Noodles, Shampoo, Toothpaste, Other Products. Category order is the order categories first appear in the base `data.js` (Cigarettes, Hot Water, Drinks, ...), then new categories A–Z, with Other Products last; products are A–Z within each category (`Catalog.sortProducts`). `renderProducts()` starts a new section header whenever `category` changes, so a category's products must be contiguous. Only Hot Water (via `HOT_WATER_PRODUCTS`), Cigarettes and Drinks get a colored left edge (`.color-bar`) and tinted type badges; other categories render as plain cards.
- **Product catalog**: `data.js` is the base; in-app changes are a small change set (`{added, edited, removed}`) in localStorage `honesty-store-catalog` (`catalogChanges`), layered on `BASE_CATALOG` (a copy of `data.js` taken at load). `applyCatalog()` rebuilds `PRODUCTS` / `HOT_WATER_PRODUCTS` **in place** (other code holds references) and prunes changes that no longer differ from the base, e.g. after `data.js` is replaced. Every change goes through `commitCatalog(newChanges, message)` (apply, re-render, Undo toast). Corrupt JSON, or valid JSON whose entries make `Catalog.build` throw, loads as no changes (`startCatalog()`) and the raw value is kept once in `honesty-store-catalog-corrupt-backup`. The Products modal (`openProducts(tab)`, header button / phone More menu) has tabs All products (inline price/category/hot water edit, remove with a Removed(n) restore list, per-row reset), Add one (duplicate check; re-adding a removed base product restores it) and Add many (paste name, price, category, `hw`; preview New/Exists/Same/Problem; one commit). The footer shows "N change(s) not in data.js yet" and `downloadDataJs()` saves a new `data.js` to replace the file. The catalog key is part of `backupAll()`; `restoreBackup()` only fills it in when missing locally, then reloads it. Past transactions keep their stored `unitPrice`.
- **State**: Transactions stored in-memory (`transactions` array) and persisted to `localStorage` keyed by date (`honesty-store-YYYY-MM-DD`). Each transaction has: `id`, `time`, `customer`, `product`, `qty`, `unitPrice`, `hotWater`, `paid`, `totalPrice`.
- **Product Modifiers**:
  - Hot Water products (`HOT_WATER_PRODUCTS`): toggle checkbox adds `HOT_WATER_FEE` (+₱5) per item, checked by default. Per-product fees in `HOT_WATER_FEE_OVERRIDES` (Malungay: +₱2); always get the fee via `hotWaterFee(name)`. The +fee comes from `HOT_WATER_PRODUCTS`, not the `Hot Water` category.
  - Hot water is stored as `t.hotWater` and shown as `(+HW)`. Older saved data may have product names with a suffix (e.g., `Malungay (+Cup)` from the removed "With Cup" option), so keep using `startsWith(p.name + ' (')` when matching transactions back to products.
- **Transaction Log**: `renderLog()` renders **every** transaction for the session (newest first) — there is no row cap, so nothing is unreachable. It preserves `#txLogBody.scrollTop` across re-renders (marking paid, undo) and always reveals a new sale: `addTransaction()` sets `newLogTxId`, so the next render expands a collapsed log, scrolls `#txLogBody` to the top, and flashes that row (`.tx-new`). The header badge `#txLogCount` shows the row count, and turns into a clickable blue "<name> only (n) ✕" chip when `customerFilter` is set — clicking it calls `clearCustomerFilter()`. `toggleTxLog()` collapses the body (`.tx-log-body.collapsed`) and rotates the chevron.
- **Total Sales card** (`#statSalesCard`, `renderSalesCard()` called from `renderStats()`): `addTransaction()` sets `saleSplash`, so the next render drops a `.sales-drop` into the card (ripple + burst bubbles) and counts the number up from `salesShown`. Daily goal is stored in `honesty-store-goal` (`getSalesGoal()`, set via `setSalesGoal()` using `modalPrompt()`); `--goal-fill` raises `.sales-fill` and the waves, and crossing the goal on a sale flashes `.goal-hit` + a toast. The goal button (`#salesGoal`) is a solid pill whose background doubles as a progress bar (`--pill-bg` / `--pill-fill` with `--goal-fill`), shows a flag icon, and turns green with a trophy icon (`.done`) once the goal is reached. In dark mode the card's water, bubbles and splash use deep blue instead of white.
- **Unpaid panel** (`#owesPanel`, `renderOwes()`): customers who still owe today, biggest amount first, each with a Mark paid button (`markCustomerPaid`), plus a "From past days" group (see Past-days unpaid). Hidden when there is nothing today and no past debt. At ≥1180px it becomes a sticky right sidebar (`.main-container:has(#owesPanel:not([hidden]))` switches to a two-column grid and widens the header to match).
- **Quick sell** (`#quickSell`, `renderQuickSell()`): "Selling to" chips set `sellTo` (`setSellTo()`, which then scrolls the first visible product category under the header); while set, each product header shows a `.quick-add` "+ name" button that adds 1 for that customer, and `addTransaction()` skips the scroll-to-top. At ≥1280px `#quickSell` is a sticky left sidebar (Top today cards stack vertically, `#sellStrip` is hidden since the sidebar shows the selection); with the Unpaid sidebar the page is three columns. "Top today" shows the 5 best-selling products this session as `.top-card`s: `quickTop(idx)` adds 1 for `sellTo`, or opens and scrolls to that product when no customer is picked.
- **Phone bottom bar** (`#mobileBar`, shown at ≤480px): Total, Unpaid and a Summary button, updated in `renderStats()`.
- **Calm mode** (`toggleCalmMode()`, header `#calmModeBtn`, saved as `honesty-store-calm`): `body.calm-mode` hides bubbles / glow / ripples, stops the wave and bob animations, and resets the water cursors. Use `motionOff()` (reduced motion or calm mode) before starting JS-driven effects. `body.page-hidden` (set on `visibilitychange`) pauses all animations while the tab is in the background.
- **Safe text**: customer / product names (especially typed guest names) must go through `esc()` when put into HTML and `jsArg()` when passed as an argument inside an inline `onclick="..."` — never `'${name}'`. `addGuest()` also strips `<>"\`` and caps names at 30 characters.
- **Toasts** slide in at the upper right, just below the sticky header (`top` uses `--header-h`), so they never cover the header buttons. `showToast(message, type, { label, onClick })` adds an action button and keeps the toast up for 5s; every sale shows an Undo that calls `removeTransaction(id)` (no confirm). The log's Undo column still uses `undoTransaction()` with a confirm.
- **Backup & restore**: `backupAll()` downloads every `honesty-store*` localStorage key (except the backup bookkeeping keys) as `Honesty-Store-Backup-YYYY-MM-DD.json` (`{ app, version, exportedAt, data }`). `restoreBackup()` merges: missing days are added, a day in both keeps whichever has more transactions, settings only fill gaps. `renderBackupBanner()` shows a weekly reminder (`honesty-store-last-backup`, "Later" snoozes for the day via `honesty-store-backup-snooze`). Buttons live in History and the phone More menu.
- **Customer debts modal** (`#debtModal`): tapping an Unpaid row (Today or From past days; the Mark paid buttons stop propagation) calls `openDebts(name)`, which snapshots every unpaid item for that customer across today and saved days into `debtView`. `renderDebts()` lists them grouped by day (Today first) with a paid checkbox each; the list stays fixed while open so mis-ticks can be unticked. `setDebtPaid(date, id, paid)` writes today's items to `transactions` (then `saveToStorage()`) and past items back to that day's storage (`invalidatePastOwes()`); "Mark all paid" uses it for every listed item.
- **Past-days unpaid**: the Unpaid panel also lists debts from earlier dates (`getPastOwes()`, cached in `pastOwesCache`). Call `invalidatePastOwes()` whenever saved history changes (delete day, Add Past Day, restore, New day). `markPastPaid(name)` writes paid status back to each day's storage.
- **Search**: typing calls `filterProducts(true)`, which scrolls the first matching category under the sticky header (`scroll-margin-top` uses `--header-h`, kept current by `trackHeaderHeight()`); `#productList` has a min-height so short results can still reach the top. `#noResults` shows when nothing matches. Keyboard: `/` focuses search; in search, Enter adds the first match for `sellTo` (or opens it), Escape clears (`onSearchKey()`).
- **Sticky "Selling to" strip** (`#sellStrip`): shown while `sellTo` is set, sticks under the header with Change / Stop.
- **Phone header**: at ≤480px only Summary, History and `#moreBtn` show; `toggleMoreMenu()` builds `#moreMenu` with Auto-save, Export, Import, New day, Back up, Restore, Calm mode and Dark mode.
- **Payment Tracking**: Paid status is tracked **per-transaction** (`t.paid` boolean), not per-customer. Each transaction row in the log has its own paid checkbox. Customer balance chips show unpaid amount vs total. The chip checkbox marks all unpaid transactions for that customer as paid. New purchases are always unpaid — previously paid items remain paid.
- **Daily History**: Past days' data stored in localStorage with a date index (`honesty-store-dates`). `showHistory()` shows an earnings summary (Today, Last 7 Days, This Month, All Time, Total Paid/Unpaid), a "Last 14 days" bar chart (`.history-chart`, tallest day highlighted, bars with data open that day), "Best sellers" (`renderInsights(range)`: top products, top customers and hot water fees for 7 days / this month / all time, using `historyDays` from the last `showHistory()`), then days newest-first grouped by month with month subtotals and per-day unpaid amounts. Users can view, export, or delete history per day. The day view (`viewHistoryDate(date, view)`) has a "History" back button next to the date (`.history-day-head`, plus Back at the bottom), and `.summary-tab` chips under the date: All (newest first), Customer A-Z (sorted by customer ascending), Paid / Unpaid (filter by status, view keys `:paid` / `:unpaid`), then one chip per customer (A-Z) that filters to that customer. Paid and Unpaid amounts for the shown rows sit above the total. "Add Past Day" (`importPastDay()`) files an exported workbook under its own date (from the `YYYY-MM-DD` in the filename, else the first transaction's time) without touching the current session. Dates are displayed via `formatHistoryDate()` (e.g. `Sun, Oct 4, 2026`), which parses `YYYY-MM-DD` as a local date — never use `new Date('YYYY-MM-DD')` (parsed as UTC).
- **Sales Summary**: on a filtered view (customer / Paid / Unpaid) a Back button + view name sits above the tabs (`#summaryHead`, rendered in `renderSummaryTabs()`, hidden on All); `summaryBack()` returns to All. `renderSummaryContent()` shows a table grouped by customer. `summaryView` tabs: All (customers A-Z), Paid / Unpaid (`:paid` / `:unpaid` filters), then one tab per customer. The Paid / Unpaid chips use `.tab-paid` / `.tab-unpaid` (shared with the history day view, which also has a `.tab-sort` Customer A-Z chip). The table has a Paid/Unpaid column per row, paid / unpaid amounts on each customer total row, and Total Paid (green) and Total Unpaid (red) lines above the Grand Total. Uses `.summary-paid` / `.summary-unpaid` classes.
- **Excel Export**: `exportTransactions()` generates `Honesty-Store-YYYY-MM-DD.xlsx` with 3 sheets (Transactions, By Customer, By Product). Uses xlsx-js-style for cell coloring: Paid column green/red per row, Total Paid row green, Total Unpaid row red, Grand Total row blue on all sheets. Transactions sheet does not have a Hot Water column — modifier info is appended to the product name.
- **Auto-save**: The `AutoSave` object overwrites one user-chosen `.xlsx` file after every change, via the File System Access API (`showSaveFilePicker` → `createWritable`; Chrome/Edge desktop only — the header button is hidden elsewhere). `saveToStorage()` calls `AutoSave.schedule()` (300ms debounce, writes serialized). The workbook comes from `buildWorkbook(txs)`, shared with `exportTransactions()`. The file handle + session date are stored in IndexedDB (`honesty-store` db, `kv` store, key `autosave`); after a reload the button shows "Resume Auto-save" until the user clicks to re-grant permission. States: off / paused / saving / on / error (e.g. file open in Excel; the next change or a click retries). `clearAll()` stops auto-save so the previous day's file isn't overwritten. `renderAutoSave()` updates the button.
- **Excel Import**: `parseWorkbook()` reads the Transactions sheet for rows, then the By Customer sheet to restore per-transaction paid status. It is used by History's "Add Past Day" (`importPastDay()`); there is no longer a header Import button that replaces the current session.
- **Custom Modals**: All confirmations and alerts use `modalConfirm()` / `modalAlert()` (Promise-based async) instead of native `confirm()`/`alert()`. Functions using them must be `async`.
- **Timestamp format**: `Oct 3 - 01:29 PM` generated by `getTimestamp()`.
- **Session date (`TODAY`)**: Computed by `getLocalDate()` (wraps `getLocalDateOf(date)`) using local time — never use `toISOString()` for dates (it's UTC, 8 hours behind PH time, so it gives yesterday's date before 8 AM). `TODAY` is a `let`, set at page load and refreshed by `clearAll()` ("New" button), so a session left open past midnight keeps its original date until a new session starts. It drives the storage key and export filenames. On load, `migrateUtcDates()` runs once (flag `honesty-store-date-fix-v1`) to re-file data saved under the old UTC keys by each transaction's `time` date; the original data is kept in `honesty-store-backup-before-date-fix`.

## Key Conventions

- Currency is Philippine Peso (₱ / `&#8369;`).
- CSS uses custom properties (`:root` variables) for theming. Dark mode overrides the same variables in `body.dark-mode`; with no saved preference, `loadDarkMode()` follows `prefers-color-scheme`. Use `--on-primary` (not `white`) for text on `--primary` backgrounds, since the dark-mode accent is light.
- Visual system (water refilling theme): ocean-blue tinted neutrals + one blue accent (`--primary`, also `--drink`). Green / red / amber are only for paid / unpaid / warning state; `--hot-water` (orange) and `--cigarette` (green) only mark categories. Header is a deep-water band (`--header-deep` → `--header-bg` gradient) with two layered wavy edges (`header::after` solid, `header::before` lighter `--header-wave`, both CSS masks) that drift in opposite directions (`@keyframes header-wave`), and translucent buttons with a hover sheen. Inside it, `.header-water` (built by `initHeaderWater()`) holds a pointer-following glow (`--mx` / `--my`), two inner `.hw-wave` layers, rising `.bubble`s, and tap ripples (`.ripple` + burst bubbles, skipped on controls and under reduced motion). The brand drop bobs and splashes on tap (`splashBrand()`); Behind the page content, `#pageWater` (fixed, `z-index: -1`) has slowly drifting light (`.pw-light`), two waves along the bottom of the screen (`.pw-wave`), and faint `.page-bubble`s rising the full height (`initPageWater()`); all tinted from `--primary`, so it adapts to dark mode, and calm mode hides/stops it. only Summary uses the light-blue `--header-cta`, and History (`.btn-history`) is solid lavender so it also stands out. The Total Sales stat (`.stat-sales`) is a larger-value card with a `--primary-dark` → `--primary` gradient, a water-drop label icon, and two translucent wave layers (`::before` / `::after`, CSS masks) drifting along the bottom via `@keyframes sales-wave`. `initSalesBubbles()` adds a few smaller rising `.bubble`s to it (shared with the header via `makeBubble(x, { container })`). The Paid stat (`#statPaidTank.stat-tank`) is a water tank: `renderStats()` sets `--fill` (paid / total sales) and the label's `data-pct`; the fill rises via a `transform` transition. Empty states use `.empty-note` (water-drop icon). Toasts show a `water_drop` icon via `.toast::before` (`undo` for undo toasts). Radii: cards `--radius` 12px, modals `--radius-lg` 16px, controls `--radius-sm` 8px, chips / tags / search full pill. Money and counts use `--mono` (Geist Mono). Animations are disabled under `prefers-reduced-motion`. Avoid em-dashes in UI text.
- After any state change, call `renderAll()` which calls `renderProducts()`, `renderQuickSell()`, `renderLog()`, `renderOwes()`, `renderCustomerTotals()`, and `renderStats()`.
- After state mutations, call `saveToStorage()` before `renderAll()`.
- Product cards are collapsible; `toggleProduct(idx)` handles expand/collapse. The header Expand/Collapse-all button (`#toggleAllBtn`) is hidden.
- Bulk and Guest qty inputs use a `.qty-stepper` (large −/+ `.qty-step` buttons calling `stepQty(id, delta)`, min 1) instead of the native number spinner arrows, which are hidden. The Bulk customer `<select>` is wrapped in `.select-wrap` with `appearance: none` and a large `expand_more` icon (`.select-arrow`, `pointer-events: none`) in place of the native arrow.
- The search bar filters product cards by `dataset.name` and hides empty category headers.
- `beforeunload` event warns users if there are unexported transactions — skipped when auto-save is on and fully written; warns if an auto-save is pending or failed.
- Cursors are water-themed SVG data URIs in `:root`: `--cursor-bubble` (default, on `body`) and `--cursor-drop` (anything clickable). Use `cursor: var(--cursor-drop)` instead of `cursor: pointer`.
- Icons use Material Icons Round via the `.icon` class with ligature text content.
- The "New" button clears all transactions to start a fresh session.
- Responsive breakpoints: 768px (tablet), 480px (mobile).
